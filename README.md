# 求职工坊 JobKit

一个工具：**把"我做过什么"沉淀成母版，然后针对每份 JD 自动生成简历、出模拟面试题、用 AI 把档案问清楚。**

两种打开方式：

| 方式 | 命令 | 能用什么 |
|---|---|---|
| 直接开 | 双击 `index.html` | ①–⑤ 全部规则功能，不联网 |
| 本地服务 | `python serve.py` → `http://127.0.0.1:8770` | 上面全部 + **⑥ AI 助手** |

数据只存在你自己的浏览器里，AI 的 Key 只存在你自己的电脑上。

---

## 六个模块

### ① 我的档案 —— 母版
所有内容的唯一来源。以后写简历、出面试题都从这里取，不从记忆里现编。

- **基本信息**：留空的字段不会出现在简历里
- **档案完整度**：12 项硬指标（姓名、联系方式、项目时间、岗位名、量化结果……）实时打分，点条目直接跳到要填的地方
- **时间线补全**：按「工作年限 + 入职起点」铺一条建议时间线，一键采用。采用后会标 **推定**，点 ✓ 或改成真实值才算核实
- **技能池**：每项技能标三档真实度
  - 🟢 **真做过** → 简历可以写"负责/主导"
  - 🟡 **参与/设计过** → 只能写"参与/设计/评估"
  - 🔴 **只是了解** → **不进简历**，面试被问到说"了解原理、没实操"
- **项目经历**：一条动作一行，写"做了什么 + 怎么做的 + 结果"
- **工作经历 / 教育 / 其他**

> 这个分级是整个工具的地基。简历里最容易翻车的一句话是"熟练使用 XX"，而 XX 只是看过文档。标清楚，写的时候工具会拦住你。
>
> 🟡 的技能不会被塞进技能清单主行，而是单独一行标成「参与 / 设计过」——关键词还能被 ATS 扫到，但你不会替自己宣称会。

### ② JD 分析
粘贴 JD（或尝试从链接抓取），自动产出：

- **匹配分**：技能覆盖 40 + 项目相关 40 + 加分 20 → A/B/C 档
- **关键词命中**：绿=能写、黄=只能写"参与"、红=不要写，括号里的 ×N 是 JD 里出现的次数
- **缺口清单**：JD 要但你没有的，明确标"别写进简历"
- **硬性门槛**：年限、学历是否达标
- **隐性偏好**：从措辞读出来（"从 0 到 1"=要能主导，"配合团队"=执行向，"闭环"=要业务结果）
- **红旗**：外包/驻场、加班暗示、职责不清

### ③ 生成简历
点一下，按 JD 重排出来：

- 项目自动按相关性排序（最相关的排第一）
- 每个项目自动挑最相关的 5 条 bullet
- 技能按 JD 命中优先、分类固定顺序，「参与/设计过」单独一行
- 摘要按岗位风格生成（AI 应用 / 后端 / 数据 / 通用），只取你真做过的技能
- 有 JD 时，求职意向自动用 JD 的岗位名

**右侧质检**做两件事：

1. **硬拦截**：缺姓名、缺电话/邮箱、项目没写时间、工作经历没时间 → 红条「先别投」
2. **软提醒**：能写的关键词覆盖多少、有没有把"只是了解"写进去、"待补"剩几处、有没有一个量化数字

简历区域可以直接编辑。改完点「打印 / 存 PDF」，打印样式会自动隐藏所有界面元素，只输出 A4 简历。

### ④ 模拟面试
题目是**当场组合**的，每次都不一样：

- 从你的项目里生成项目题（介绍、最难的点、重做会改什么）
- **从 JD 缺口里生成压力题**：JD 要求、但你只标了"参与/设计"或完全没做的，按你的真实度给不同话术
- 从 JD 关键词映射到通用题库（技术选型、数据、评估、部署、故障排查），按 JD 相关度排序，不按题库顺序
- 补上行为与动机题

每题可以：计时 → 自己说一遍 → 点「看答题骨架」→ 对照追问 → 自评 1-5 星。

> 顺序很重要：**先说，再看答案**。看完再说的练习几乎没有效果，因为你在回忆而不是组织。

### ⑤ 复盘
累计各维度得分，找出薄弱环节。薄弱维度不是靠背答案补的，是回档案里把那一块的真实素材写厚。

### ⑥ AI 助手 —— 需要 `python serve.py`
三种模式共用一个对话框，但提示词和输出格式完全不同。

**1. 对话建档案**
它一个问题一个问题问你（每轮最多 2 个，不让你面对一张空表单），答完自动抽成结构化档案。
每凑齐一段经历，会弹出一张**变更卡片**：左边是你档案里的原值，右边是即将写入的新值，你点「写入档案」才生效——**AI 不会悄悄改你的档案**。

它的规则里写死了：不编数字、不编技术栈、不写用户没说的职责；用户说"记不清"就留空标「待补」。你说"负责整个系统"但实际只做了一个模块，它会当场提醒并记录真实边界。

**2. 改写简历**
选一个项目 → 逐条改写 → 逐条「采用」。铁律是**只改措辞不改事实**：

- 不新增原文没有的技术、数字、职责
- 不升级动词（"参与"不能变"负责"）
- 原文没有量化，改写后也不会有，只会在理由里提示"建议补真实数字"

所以它是个"措辞顾问"，不是"代笔"。

**3. 模拟面试**
AI 扮演面试官，拿你的档案 + JD 出题，专挑站不住的地方问：模糊的量化、过大的动词、JD 要求但简历空白的技能。每题回你 **点评 → 更好的答法 → 下一个问题**。

> 和 ④ 的区别：④ 是固定题库 + 规则映射，题目可预测、可以反复刷；⑥ 是活的，会根据你的回答往下追，练的是临场。两个都要用。

**配置 Key**：点右上角「配置 Key」，贴 DeepSeek 的 key（platform.deepseek.com 申请）。Key 写进本机 `config.json`，**已加入 .gitignore，不会进仓库**，也不经过任何第三方服务器——浏览器只跟本机的 `serve.py` 说话，由它转发给模型。

## 三分钟上手

1. 打开 `index.html`（想用 AI 就改成 `python serve.py` 后开 `http://127.0.0.1:8770`）
2. 进「⑥ AI 助手」→ 配置 Key → 点「开始」，让它一个问题一个问题问你把经历说清楚
3. 进「① 我的档案」核对它抽出来的内容，删掉示例项目
4. 进「② JD 分析」，贴一份你真正想投的 JD，点「分析 JD」
5. 进「③ 生成简历」，看着改，改完打印成 PDF
6. 投出去之前，进「④ 模拟面试」跑 12 题，再进「⑥ 模拟面试」让 AI 追你两层

> 首次打开预置了一份**纯虚构的示例档案**，方便你看清结构和填法。点右上角「清空重来」就能换成自己的。仓库不含任何真实个人信息。

## 关于联网

静态网页无法直接抓招聘网站（都有登录墙和跨域限制），所以：

- **抓取**：内置了公共文本代理，只对公开页面有效，抓不到会提示你手动粘贴
- **检索**：模拟面试页提供「搜该公司面经」「搜该岗位高频题」的快捷搜索，结果自行甄别

如果想让工具真正"读懂"JD 并生成定制文案，需要接大模型 API。现在接了，但**只在 ⑥ 里用，而且必须由你启动本地服务**：

- ①–⑤ 全是规则算法，一个 token 都不烧，结果可解释、可复现
- ⑥ 才调模型，用来做规则做不到的事：追问、抽取、改写、临场对话

这个分工是刻意的。如果全交给模型，你会分不清"这个分数是算出来的还是编出来的"。

## 数据

- 全部存在浏览器 localStorage，不上传
- **边填边自动存**：顶栏右上有「已自动保存 时:分:秒」，看到它就说明写进去了
- 想手动确认就点「保存」，或按 `Ctrl / Cmd + S`（切标签、关页面时也会自动存一次）
- 右上角「导出档案」生成 JSON 备份，「导入」可恢复或换设备
- 清浏览器数据会丢，建议每周导出一次

## 已知局限

| 局限 | 影响 | 绕法 |
|---|---|---|
| 技能词典是内置的（约 85 项常见技术栈） | 冷门技术识别不到 | 档案里直接写标准名，简历照样能生成 |
| 匹配分是规则算的，不理解语义 | 同义表述可能漏判 | 用 JD 的原词写项目动作 |
| 不做真实 AB/埋点 | 无法验证投递效果 | 靠「投递记录」自己统计 |
| 无后端 | 不能多人协作 | 导出 JSON 传给对方导入 |
| ⑥ 依赖模型输出的 JSON 格式 | 模型跑偏时变更卡片不出现（正文会正常显示） | 重发一次，或换个更明确的说法 |
| ⑥ 会产生 token 费用 | 一次访谈大概几分钱 | ①–⑤ 完全不花钱，可以只手动填档案 |

## 文件结构

```
求职工坊/
├─ index.html          界面
├─ serve.py            本地服务：静态托管 + 模型接口转发（AI 功能必需）
├─ config.example.json 配置样例（复制成 config.json 填 key，config.json 不进 git）
├─ 自测报告.md          本地私有文件（已 gitignore，含开发者个人材料，不随仓库分发）
├─ assets/
│  ├─ style.css        样式（含 A4 打印样式）
│  ├─ data.js          技能词典 · 措辞提示 · 面试题库 · 示例档案
│  ├─ app.js           分析 / 打分 / 生成 / 出题 逻辑
│  └─ ai.js            ⑥ AI 助手：提示词 · 流式输出 · 档案变更卡片
└─ _test/              开发自测脚本（不影响使用）
   ├─ selfqa.js        三份 JD 的回归测试，输出打分/关键词/题目/简历正文
   └─ logic-test.js    纯函数级单测
```

改完逻辑跑一次 `node _test/selfqa.js`，对比输出里的 `parts`（技能/项目/加分三项）就知道有没有回归。

### 换模型

`config.json` 里改 `base_url` 和 `model` 即可，只要是 OpenAI 兼容的 `/chat/completions` 接口就行（通义、Kimi、智谱、本地 Ollama 都支持）。也可以不改文件，直接在页面「配置 Key」里填接口地址。
